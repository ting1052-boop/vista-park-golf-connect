# codex 명세 — 고객 예약앱 UI 1차 (삭제·이동만)

작성일: 2026-09-11 · 대상 파일: `src/app/member/app/page.tsx` **단일 파일**
성격: **로직 변경 없음.** 블록 삭제 3건 + 위치 이동 2건. 상태·쿼리·제출 흐름은 그대로 둔다.
배경: 시니어 고객 기준으로 "예약이 화면의 주인공이 아님"이 문제. 블록 11개 → 6개.

작업 규칙은 `docs/codex-handoff-20260712.md` §0을 따른다.

---

## 1. 삭제 — "관리자 확인" 링크 (버그)

고객 화면에 관리자 페이지 링크가 있다. 고객이 누르면 로그인 벽에 막힌다.

- 위치: `page.tsx:993` `<Link href="/admin/reservations">관리자 확인</Link>`
- 조치: 해당 `<Link>` 삭제.
- 남는 "예약 내역"(`/member/scorecard`) 링크는 **유지**하되, 2열 그리드가 1개만 남으므로
  `grid-cols-2`를 단일 버튼 레이아웃으로 정리.

## 2. 삭제 — 하단 아이콘 4개 (작동하지 않음)

`<footer>`의 매장/예약/타석/내역 4개가 `<span>`이라 **눌러도 아무 반응이 없다.**
시니어는 반드시 눌러보고 고장으로 인식한다.

- 위치: `page.tsx:998~1013` `<footer className="mt-5 grid grid-cols-4 ...">`
- 조치: `<footer>` 블록 통째로 삭제. 사용하지 않게 되는 아이콘 import(`MapPin`,
  `MonitorCog` 등)도 함께 제거해 lint 경고를 남기지 않는다.

## 3. 삭제(조건부) — 비로그인 시 "예약 현황" 섹션

비로그인 상태에서는 **남의 예약**을 날짜·타석만 보여준다. 고객에게 가치가 없고
"벌써 다 찼나?"라는 오해만 만든다.

- 위치: `page.tsx:935~975` (제목이 `{memberUserId ? "내 예약" : "예약 현황"}`인 `<section>`)
- 조치: `memberUserId`가 있을 때만 렌더. 비로그인이면 섹션 자체를 렌더하지 않는다.
- 로그인 상태의 "내 예약"은 그대로 유지.
- 비로그인용 안내문("개인정보 보호를 위해 …")도 함께 사라진다.

## 4. 이동 — 앱 설치 / 소셜 로그인 블록을 폼 아래로

지금은 예약 폼보다 **위**에 있어, 시니어가 "카카오로 시작"을 필수 로그인으로 오해한다.
실제로는 로그인 없이 예약이 가능하다.

- 대상: `page.tsx:652` `<PwaInstallCard />`, `page.tsx:654~656` `<SocialLoginPanel />` 감싼 `div`
- 조치: 두 블록을 **"예약 안내"(주황 카드) 다음, 하단 링크 위**로 이동.
- 컴포넌트 자체는 수정하지 않는다. JSX 위치만 옮긴다.

## 5. 이동 — "예약자 정보"를 맨 뒤로 (순서 재배치)

무엇을 예약할지 보기도 전에 이름·전화부터 요구하는 순서라 진입장벽이 크다.
표준 예약 순서(무엇을 → 언제 → 누가)로 바꾼다.

- 대상: `page.tsx:702~735` 안의 "2. 예약자 정보" 헤더 + 이름/전화 입력 `div`
- 새 순서 및 번호:

| 새 번호 | 섹션 | 비고 |
|---|---|---|
| 1 | 예약 매장 | 그대로 |
| 2 | 날짜와 시간 | 기존 "3." → **"2."** |
| 3 | 이용시간 | 기존 "4." → **"3."** (타석 선택 select 포함, 이번엔 그대로 둠) |
| 4 | 예약자 정보 | 기존 "2." → **"4."**, 이용시간 블록 **뒤**로 이동 |
| 5 | 예약 확인 | `isReviewing` 시 노출, 그대로 |

- 섹션 제목 번호를 위 표대로 **전부 다시 매긴다**.
- 예약자 정보 블록은 "4. 이용시간" 관련 안내문들(`approvalRequired` 안내 포함) **뒤**,
  `isReviewing` 확인 블록 **앞**에 위치시킨다.
- `validateReservationInput()`의 검증 **순서나 내용은 바꾸지 않는다.** 이름/전화 미입력
  시 기존 에러 메시지가 그대로 나오면 된다.

## 하지 않을 것 (이번 범위 아님)

- 매장 드롭다운 조건부 숨김 / 타석 있는 매장만 노출 → 2차 (핸드오프 C와 함께)
- 타석 선택 select 숨김 → 2차
- 안내문 4개 통합 → 2차
- 선택 불가 시간 슬롯 숨김 → 3차
- **하단 고정 CTA(`page.tsx:1018~`)는 건드리지 않는다.** 현재 구조가 좋다.
- 스텝 위저드 전환 안 함. 섹션 번호가 이미 단계 역할을 한다.
