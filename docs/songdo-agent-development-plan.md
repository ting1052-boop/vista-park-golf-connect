# 송도파크자이 Agent 사용 현황·무인제어 개발서

> 2026-10-04 최종 재검토: 이 문서는 초기 설계 이력으로 보존한다. 최신 기준은 [최종 구성 및 출시 검토](songdo-agent-release-review-20261004.md)다. 특히 시작 후 고정 60분, 코스 진입 시 시작, unknown을 대기로 바꾸는 해석은 채택하지 않는다. 송도 정시 이용창과 START 이후 모드 선택 입장 기준을 적용하며 실제 감지 신호는 별도 검증이 필요하다. 현재 구현은 출시 조건 미충족이다.

작성일: 2026-10-04 (Asia/Seoul)
상태: 개발 기준서. 2026-10-04 최종 구현은 별도 검토서의 구현 상태와 출시 조건을 따른다. 현장 설치·운영 배포는 하지 않았다.
대상: 송도파크자이(VISTA-XII). 기존 공용 Windows Agent의 송도 설정을 보완한다.

## 1. 목적과 결정사항

관리자는 예약 절차 없이 대시보드에서 타석을 켜고 끄며, 구역별 운영시간을 설정하고, 사용 상태·경과시간·오늘 이용 시작 횟수를 확인할 수 있어야 한다. 송도 Agent는 사용 현황 보고와 PC 정상 종료 명령 실행을 함께 담당한다. 실제 타구·홀 번호·완주 여부는 이번 개발의 필수 조건이 아니다.

사용자 추가 확인: **예약 기능은 사용하지 않지만 타석 무인제어는 필수다.** 이 문서의 관찰용 이용창은 사용시간의 판정 방식을 뜻하며, Agent나 대시보드를 읽기 전용으로 제한한다는 뜻이 아니다.

- 골프와 파크는 동일 EXE를 사용하고 감지 설정만 구분한다.
- 송도는 `monitorOnly`를 유지한다. 고객 종료 안내·화면 잠금·이용시간 만료에 따른 PC 종료를 넣지 않는다.
- 고객 이용을 시작했다고 판단한 순간부터 60분 고정 이용창을 만든다. 도중 입력이나 잠깐의 부재로 시간이 늘어나거나 줄어들지 않는다.
- 인증 없이 사용 신호로 다음 이용을 시작할 수 있다는 사용자 의사를 따른다. 과금·입주민 식별·아파트너 권한 검증은 하지 않는다.
- 화면에는 `이용 중`, `대기 중`, `상태 확인 불가`를 중심으로 표시한다. 여기서 이용 중은 관찰된 신호에 따른 60분 이용창이며 실제 재실을 보장하지 않는다.
- 60분 만료는 관찰용 시간 종료다. 게임을 메인으로 돌리는 동작, PC 종료, HA 장비 OFF와 연결하지 않는다.
- 관리자 또는 운영 스케줄이 발행한 정상 종료 명령은 기존 경로로 계속 처리한다. 감지 실패가 명령 수신을 막지 않아야 한다.

### 필수 무인제어와 역할

| 관리자 기능 | 실행 경로 | 조건 |
| --- | --- | --- |
| 타석별 PC 켜기 | 대시보드 → 서버 → 매장 제어기 → HA WOL | 예약·이용 세션 없이 실행 가능, 대상 매장/PC 매핑 필수 |
| 타석별 PC 정상 종료 | 대시보드 → 서버 → 해당 PC Agent → Windows 정상 종료 | HA 없이도 Agent가 연결돼 있으면 수행 가능 |
| 타석 프로젝터 등 장비 ON/OFF | 대시보드 → 서버 → 매장 제어기 → HA | 실제 연결된 장비만 제어, 마지막 명령과 실제 상태 구분 |
| 골프/파크 구역 켜기·끄기, 매장 전체 제어 | 위 경로에 명시한 대상 목록 전달 | 골프 켜기 A-01~06 / 끄기 A-01~07, 파크 P-01~02 |
| 구역별 운영시간 자동제어 | VISTA 시간표 → 상시 매장 제어기 조회 → 해당 명령 실행 | Agent에 중복 기상/종료 스케줄을 만들지 않음 |

꺼진 PC를 Agent 자체가 깨우는 구조는 아니다. 켜기는 상시 켜진 제어기와 HA가 수행하고, 정상 종료는 실행 중인 PC Agent가 수행한다. 예약이 없다는 이유로 제어 버튼을 막거나 access session 생성을 요구하면 안 된다.

수동 종료 시 이용 신호가 있으면 현재 이용 중임을 알리고 기존 확인 절차로 진행한다. 이용 상태가 불명확하면 그 사실을 표시한다. 운영 마감은 저장된 스케줄 정책에 따라 실행하며 60분 관찰창 때문에 무기한 종료를 연기하지 않는다. 관찰창 만료 자체는 전원 명령을 만들지 않는다. 게임 대기화면 잠금/해제와 자동 메인 복귀는 이 전원·장비 제어와 별도 기능이며 이번 범위에 추가하지 않는다.

과거의 상단 `00:00:00` 오버레이·자동 메인 복귀 제안은 이후의 "사용 여부만" 요청에 따라 이번 필수 범위에서 제외한다. 고객 화면에 새 카운터를 띄우지 않고 경과시간은 관리자 화면에서 보여준다.

## 2. 타석과 PC 구분

| 물리 시설 | 서버 타석 코드 | 기존 USB 로컬 키 | 역할 |
| --- | --- | --- | --- |
| 골프 1~5번 | A-01~A-05 | SD-R-01~SD-R-05 | 각 1대 |
| 골프 6번 우타 | A-06 | SD-R-06 | 6번 타석 우타 PC |
| 골프 6번 좌타 | A-07 | SD-R-07 | 같은 물리 타석의 별도 PC |
| 파크 1~2번 | P-01~P-02 | SD-P-01~SD-P-02 | 각 1대 |

PC는 9대, 물리 타석은 골프 6개와 파크 2개다. A-07을 삭제하거나 A-06 인증을 공유하면 안 된다. PC별 상태는 각각 보고한다. 물리 타석 점유 집계를 추가한다면 A-06/A-07은 OR로 묶고, 같은 이용자의 좌우 전환을 자동으로 식별했다고 주장하지 않는다.

PC 세팅 도구는 `VISTA-XII:A-01`, `VISTA-XII:P-01`처럼 다른 형식의 로컬 키를 만든다. 두 설치 경로를 모두 지원해야 한다. 서버 매장·타석 권한은 토큰에서 결정하며 이름이나 MAC만으로 결정하지 않는다.

전원 운영 정책: 골프 켜기는 A-01~A-06, 끄기는 A-01~A-07. 파크 켜기·끄기는 P-01/P-02. 사용자 지정 시간은 골프 05:50~23:20, 파크 09:50~21:30이었다. 원장 10월 3일 읽기 기록에는 파크 종료가 21:20으로 남아 있으므로 실제 저장값 차이는 별도 확인하고 이번 Agent 작업에서 덮어쓰지 않는다.

현재 골프 이용 상태는 메모리에만 있어 Agent 재시작 시 기준 시각이 사라진다. 실행 중 프로세스·입력 실패로 상태를 읽지 못한 경우에도 기존 이용 기록을 보존하는 처리가 필요하다. 현재 로컬 0.9.7 검증 이력은 기능 전체의 현장 성공 증거가 아니다.

## 4. 적용 범위와 설정

UI 적용 여부는 로그인 역할이 아니라 서버가 제공하는 해당 매장의 운영 정책으로 결정한다. `stores.agent_monitor_only`의 기존 경로를 활용하되, 최초 활성화는 송도에 한정한다. 다른 아파트에는 검증 후 명시적으로 적용한다. 본사 관리자가 송도를 선택해도 같은 사용 현황을 봐야 한다.

제안 설정(신규 계약이며 아직 구현되지 않음):

```json
{
  "monitorOnly": true,
  "usageMonitoring": {
    "enabled": true,
    "profile": "golf_input",
    "durationMinutes": 60,
    "allowInputRestart": true
  }
}
```

파크 profile은 `park_log`로 지정한다. 서버가 생성하는 설정과 USB 설치기가 같은 정책을 쓰도록 맞춘다. 단순히 A-01이라는 이름을 보고 송도로 분류하지 않는다. 공개 EXE에는 실제 토큰을 넣지 않는다.

기존 설정의 `false`를 무조건 무시하지 않는다. 설치 진단에서 어떤 파일의 명시적 설정이 기능을 끄는지 표시하고, 송도 대상의 설정 마이그레이션으로 해결한다. 운영자가 의도한 비활성화는 보존한다.

## 5. 공통 60분 상태 규칙

권장안: 골프·파크 모두 같은 관찰용 이용창을 사용하고 시작 신호만 다르게 한다. 파크에도 60분을 적용하는 것은 사용자의 시간 카운팅 요청에 대한 이번 설계안이며, 게임 종료 이벤트와 과금 세션 종료를 뜻하지 않는다.

| 현재 상태 | 사건 | 다음 상태와 처리 |
| --- | --- | --- |
| 초기화 | 첫 입력 스냅샷 또는 오래된 로그 | 기준점만 설정. 새 이용을 만들지 않음 |
| 대기 | 검증된 새 시작 신호 | 이용 ID 생성, 시작 시각 및 60분 종료 시각 저장, 시작 이벤트 1건 |
| 이용 중 | 클릭·메뉴 변경·홀 변경·다시 코스 진입 | 동일 이용 유지. 연장·재집계 없음 |
| 이용 중 | 화장실 등 무입력 | 원래 종료 시각까지 유지 |
| 이용 중 | 60분 만료 | 창 종료, 재시작 신호 대기. 전원·게임 화면에는 영향 없음 |
| 재시작 대기 | 만료 이후 새 게임 입력 또는 새 게임 시작 전이 | 새 이용창과 시작 이벤트 생성 |
| 임의 | 감지 실패/Agent 신호 오래됨 | 화면은 확인 불가, 기록과 종료 예정은 보존 |
| 재시작 | 유효한 로컬 이용창 복구 | 동일 ID·기존 종료 시각 유지, 새 시작 건수 없음 |

"아무 이벤트"는 게임 PC의 대상 게임 창에서 발생한 새 입력을 뜻한다. 바탕화면·브라우저·원격 지원 앱 입력이나 화면 애니메이션은 시작 신호가 아니다. 실제 게임 창에 주입된 원격 입력은 로컬 입력과 구분되지 않을 수 있으므로 유지보수 시 감지 일시중지/집계 제외 방법을 제공한다.

만료 직전 입력을 만료 직후 샘플에서 읽었다는 이유로 다시 시작하지 않는다. 입력 발생 시각을 검증하거나 만료 시 입력 기준점을 새로 잡고 다음 변화부터 수락한다. 계속 남아 있는 `playing` 값만으로 매시간 자동 재시작하지 않는다.

프로세스 정상 종료가 확인되면 관찰 종료 사유를 기록한다. 조회 실패는 정상 종료로 취급하지 않는다. 메뉴 복귀만으로 60분을 초기화하지 않는다. 일시적인 메뉴 이동으로 새 이용 횟수가 늘어나지 않아야 한다.

로컬 상태는 타석 식별자·이용 ID·시작/종료 시각·출처를 원자적으로 저장한다. 다른 타석 선택 시 이전 이용창을 승계하지 않는다. 재부팅/업데이트 중에도 이미 시작한 창을 복구하고, 만료 기록이나 이전 게임 실행의 오래된 로그로 새 창을 생성하지 않는다. 시간 역행·큰 시계 오차는 확인 불가로 처리하고 반복 시작을 막는다.

## 6. 감지 방식

### 골프 연습장

1단계는 현재 전경 입력 방식을 보완한다. 현장 보고의 `UD7.exe 01.104e`를 우선 근거로 삼는다. `ParOnGolfV5.exe`는 코드 기본 후보이며 각 PC에서 실제 사용 여부를 확인한다.

키 내용·문자·좌표를 서버로 보내지 않는다. `GetLastInputInfo` 변화는 클릭만이 아니라 마우스 이동 등에도 반응할 수 있다. 사용자 허용 범위에서는 시작 신호로 인정하되 클릭 3회 검증이나 실제 타구 감지로 설명하지 않는다. 폴링 사이 다른 앱에서 발생한 입력이 게임 입력으로 오인되는지 시험하고, 발생하면 전경 유지 확인 등 최소 보완을 한다.

화면 상단 타이머 숫자 변화 감지는 후속 선택사항이다. 현재 OCR 구현으로 간주하지 않는다. 입력 감지가 현장 기준을 충족하지 못할 때만 개인정보 없는 타이머 영역을 로컬로 판독하는 별도 실증을 진행한다.

### 파크골프

기존 ScreenGolf 상태 감지기를 재사용한다. 사용자 보고에서 메뉴·일반 코스가 확인된 P-01은 근거가 있지만, P-02를 포함한 모든 PC의 경로와 실행파일을 검증 완료로 취급하지 않는다.

게임이 실제 실행 중이고 신규 로그 전이가 메뉴에서 코스/연습으로 진입한 경우 시작 신호로 사용한다. 기존 공유 GameMode 문구 하나만으로 시작하지 않는다. 만료 후에는 새 시작 전이 또는 설정으로 허용된 대상 게임의 새 입력으로 재시작한다. 이 입력 fallback은 파크에서도 별도 시험해야 한다.

홀 OCR는 기본 비활성화한다. 홀 확인 실패가 이용 중 상태를 지우지 않게 한다. 로비 복귀와 18홀 완주는 구별하며, 로비 복귀 횟수를 이용자 수로 표시하지 않는다.

### 자동 메인 복귀 제외 근거

사용자가 제공한 UD7 현장 조사에서는 스트로크 `X → >>`, 레인지 `복귀 → O`의 수동 복귀만 확인됐다. menu/exit 로그는 확인창 단계에서 이미 발생한다. 창 제목과 UI Automation으로 메인 도착을 증명하지 못했다. 따라서 좌표 클릭·Enter·Esc·프로세스 재실행으로 자동 복귀를 구현하지 않는다. 이후 제조사 지원이나 화면 상태 판별이 검증되면 별도 과제로 다룬다.

## 7. 서버·데이터 계약

기존 heartbeat의 선택적 telemetry를 확장한다. 기존 v1/v2, 감지 미지원 Agent, 서버에 아직 새 필드가 없는 상황과 호환돼야 한다. 아래는 제안 usage payload이며 현재 그대로 전송하면 기존 검증기를 통과하지 않을 수 있다.

```json
{
  "state": "active",
  "usageId": "example-usage-id",
  "source": "foreground_input",
  "confidence": "medium",
  "startedAt": "2026-10-04T01:00:00.000Z",
  "endsAt": "2026-10-04T02:00:00.000Z",
  "observedAt": "2026-10-04T01:05:00.000Z",
  "lastInputAt": "2026-10-04T01:04:58.000Z"
}
```

source는 `foreground_input` 또는 검증된 `park_log`로 구분한다. 로그 기반에서는 lastInputAt=null을 허용한다. usage ID는 전송 재시도와 재시작에도 유지한다. 서버는 매장·타석을 인증 토큰으로 연결하고 클라이언트가 보낸 임의 매장 ID를 신뢰하지 않는다.

현재 telemetry만으로는 과거 하루 이용 횟수를 재구성할 수 없다. 별도 이용 시작 이벤트 저장소를 제안한다. 기존 outbox의 ACK·중복 방지 패턴을 재사용하되 round 이벤트와 의미를 섞지 않는다.

- 이벤트 키: 인증된 Agent/타석 + usageId + eventType의 UNIQUE 제약.
- 이벤트: usage_started, usage_ended. 종료 사유는 duration_elapsed, process_exit 등으로 구분.
- 시작/종료를 로컬 outbox에 먼저 저장하고 서버가 저장한 뒤 ACK. 실패 시 재전송하고 큐 크기·보관 기간을 제한한다.
- 한국시간 날짜의 시작 이벤트 수를 `오늘 이용 시작 N회`로 표시한다. 자정을 지나면 시작일에 1회만 센다.
- 반복 이용·동일인의 재시작·원격 입력을 구별할 수 없어 `오늘 이용자 N명`으로 표시하지 않는다.
- A-06/A-07의 합계도 사람 수가 아니다. 1단계는 PC별 횟수를 보여주고 물리 타석 중복 제거는 후속 과제다.
- 이벤트 저장 실패로 heartbeat/종료 명령을 실패시키지 않는다. 집계 미지원 또는 조회 실패는 0회와 구별한다.

DB migration과 API 계약은 구현 단계에서 작성하고 승인 후 적용한다. 서버 수용·집계 경로를 먼저 배포하고 Agent를 확대한다. 운영 적용 전 기존 데이터·RLS·매장 범위·중복 이벤트·지연 전송을 검증한다.

## 8. 관리자 화면

송도 카드의 대표 상태·이용 중 KPI·경과시간은 동일한 usage 판정 함수를 사용한다. 현재 access_sessions 기반 카드 제목과 게임 상태 행이 서로 다른 결과를 내는 구조를 그대로 두지 않는다. 관찰용 이용 시작이 예약·결제 access session을 자동 생성하지 않도록 한다.

| 상황 | 대표 표시 | 보조 정보 |
| --- | --- | --- |
| 신선한 이용창 진행 | 이용 중 | 12분 경과, 시작 시각, 오늘 이용 시작 N회 |
| 감지 정상·새 신호 대기 | 대기 중 | 새 사용 신호 대기라는 의미. 빈자리/예약 가능 보장 아님 |
| 관찰 실패·오래된 heartbeat | 상태 확인 불가 | 마지막 확인 시각, 원인은 상세에서 |
| PC 최근 신호 있음 | PC 연결 | 사용 여부와 분리 |
| 종료 명령 접수 | 종료 요청됨 | 실제 종료와 구분 |

프로그램 미실행은 진단 상세에서 표시한다. 연결 끊김을 PC 꺼짐으로 단정하지 않는다. 신호가 만료되면 저장된 `이용 중`을 계속 실시간으로 표시하지 않는다. 60분 만료 후 실제 게임이 계속될 수 있으므로 `사용 가능`보다 `대기 중`을 사용한다.

송도 카드에서 홀·라운드 상세를 필수 행으로 노출하지 않는다. 기존 시흥 표시와 권한은 보존한다. `이용 종료`가 예약 종료인지 관찰 기록 초기화인지 PC 종료인지 혼동되지 않도록, 송도 관찰 카드에 예약 종료 버튼을 그대로 재사용하지 않는다. 이번 MVP는 자동 관찰과 기존 무인제어 `PC 정상 종료`를 사용한다.

## 9. 설치·업데이트 보완

현재 설정 우선순위는 내장 기본값 → 사용자 로컬 설정 → ProgramData 로컬 설정이다. 감지 전용 monitor.config.json의 허용 필드는 별도로 적용된다. 선택 키도 ProgramData가 우선한다.

- USB 설치 경로: `%LOCALAPPDATA%\VISTA\VISTA-Bay-Agent.exe`, 사용자 설정 `%APPDATA%\vista-windows-agent`.
- 세팅 도구 경로: `C:\VISTA` 실행파일, `C:\ProgramData\VISTA\agent` 설정.
- 포터블의 임시 Electron 실행 경로는 정상일 수 있다. 임시 EXE만 교체하지 않는다.
- 설치기는 실행 중인 대상 Agent·자동실행 경로·실제로 선택된 설정 파일을 먼저 확인한다. ProgramData가 있으면 APPDATA만 고치고 성공 처리하지 않는다.
- 신규 EXE 존재·버전·해시를 먼저 확인하고 기존 Agent를 중지한다. 설정과 구버전을 백업하고 교체·기동·heartbeat 버전까지 확인한다. 실패하면 복구하며 성공 문구만 출력하지 않는다.
- 해당 PC의 타석 토큰 하나만 보존한다. EXE 교체 때문에 전체 토큰 재발급이나 SQL 재등록을 하지 않는다.
- BAT는 검증된 CRLF/호출 경로, 한글 PS1은 Windows PowerShell 5.1 호환 인코딩으로 제공한다.
- 같은 0.9.7 번호로 여러 바이너리가 존재했던 혼선을 반복하지 않는다. 후속 변경은 새 버전과 릴리스 manifest의 해시·빌드 식별자를 부여한다. 실제 다음 버전은 구현 시 최신 릴리스와 대조한다.

무인 자동 업데이트는 현재 구현 완료로 간주하지 않는다. 후속 단계에서 HTTPS 릴리스 manifest·신뢰할 수 있는 서명 검증·파일 해시·별도 교체기·이용 중 업데이트 유예·실패 롤백·송도 제한 배포를 설계한다. 현재 세팅 도구의 다운로드 URL 제공 기능은 실행 중 Agent 자동 업데이트와 다르다.

## 11. 수용 기준

1. 송도 골프/파크가 같은 EXE로 동작하고 본사 계정·송도 계정에서 동일한 타석 사용 현황을 본다.
2. 시흥 매장관리자라는 이유만으로 송도 정책이 적용되지 않는다. 다른 매장의 종료 요청·설정·상태를 참조하지 않는다.
3. 정상 부팅/프로그램 단순 실행/기존 입력/오래된 로그만으로 이용 시작이 생기지 않는다.
4. 골프 게임 창 새 입력, 파크의 검증된 새 코스 진입이 각각 이용 시작 1건을 만든다.
5. 스트로크와 드라이빙 레인지에서 사용 감지를 확인한다. 게임 외 앱 입력·창 전환·원격 작업 오탐 시험을 기록한다.
6. 20분 무입력·반복 클릭·홀/메뉴 이동에도 처음 60분 종료시각이 유지된다.
7. 만료 직전 입력·계속 남아 있는 playing 값만으로 재시작하지 않는다. 만료 후 새 신호는 시작 1건만 만든다.
8. 게임 감지 실패와 네트워크 장애는 확인 불가로 표시하고 기존 기록과 정상 종료 수신 경로를 보존한다.
9. Agent 재시작·EXE 교체·outbox 재전송에도 기존 이용 ID/종료 시각·일일 횟수가 중복되지 않는다.
10. 파크 홀 OCR를 꺼도 이용 중이 표시되며 로그에서 홀을 못 찾는다고 전체 감지를 실패시키지 않는다.
11. 60분 만료 시 실제 키 입력·게임 종료·오버레이·PC 종료·HA OFF가 0회다.
12. 자정 넘김·시계 변경·다른 타석 선택·PC 정상 종료 후 다음 부팅을 검증한다.
13. 관리자 종료 ACK와 실제 PC 오프라인을 구별하고, 스케줄 종료 정책을 관찰용 만료와 혼동하지 않는다.
14. 설치기는 복사 실패를 실패로 표시한다. 서버에서 설치된 새 버전과 타석 대응이 확인돼야 현장 완료다.
15. 예약·이용 세션 0건에서도 타석별 켜기/정상 종료, 연결 장비 제어, 구역/전체 제어가 동작한다. 송도 명령이 시흥 등 타 매장에 전달되는 경우는 0건이다.
16. HA 단절 시 장비 켜기 실패를 표시하면서 온라인 Agent의 PC 정상 종료는 유지한다. Agent 단절 시 종료 성공을 주장하지 않는다.
17. 골프 구역 켜기는 A-07·파크를 포함하지 않고, 골프 구역 끄기는 A-07을 포함한다. 파크 구역 명령은 P-01/P-02에만 전달한다.
18. 운영 스케줄은 예약 없이 실행되고, 관찰용 60분 만료와 별도로 동작한다. 기존 HA/Windows 중복 예약의 조정은 현장 확인과 승인 후 수행한다.

단위 테스트는 시간과 입력을 주입해 60분을 빠르게 검증한다. 운영 종료 명령 없이 mock으로 격리한다. 계약/권한 테스트, 기존 Agent check, 웹 타입·변경 파일 lint·빌드와 모바일 시각 검증을 실행한다. 실기기 시험은 비이용 시간에 P-01 및 A-01 한 대씩 수행하고 사용자 확인 후 확대한다.

## 12. 남은 확인과 롤백

현장 확인: 각 PC의 실행 중 Agent 버전·해시·활성 설정 경로, 실제 게임 프로세스/로그, Windows 로그인 계정과 자동실행, 파크 신규 시작 신호 반복성, 골프 원격입력 오탐, A-06/A-07 물리 대응.

운영 확인: 송도 매장 정책 DB 반영 여부, 새 usage 서버 수용 여부, 기존 예약 세션이 송도 화면에 남아 있는지, 파크 종료시간 차이, 과거 HA 전체 켜기 자동화의 현재 활성 여부. 확인 없이 운영 데이터를 지우거나 시간표를 바꾸지 않는다.

설치 실패는 해당 PC의 EXE·설정·자동실행만 백업으로 되돌린다. 집계 오류는 송도 usage 기능만 비활성화하고 heartbeat·관리자 PC 종료를 유지한다. 구버전으로 내려도 새 데이터가 파괴되지 않도록 DB 변경은 추가형으로 설계한다. 과거 이벤트를 일괄 삭제하지 않는다.

## 13. 구현자에게 전달할 지시

이 문서는 설계서이며 지금은 실행 승인이 아니다. 후속 구현 요청을 받으면 preflight, 공유 원장 전체 확인, git status, 현재 작업 등록부터 한다. 기존 미커밋 0.9.7 소스를 보존하고 단계별로 보완한다. 페이지와 관련 API는 함께 검증·커밋하고, 운영 DB 변경·배포·현장 기기 조작은 승인 범위에서만 한다. 진행 보고는 구현/검증/빌드/운영 배포/현장 확인을 구분하고 비밀값은 출력하지 않는다.
