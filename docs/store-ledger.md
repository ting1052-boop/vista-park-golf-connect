# VISTA 매장 원장

최종 갱신: 2026-09-20

매장 하나를 열고 운영하는 데 필요한 사실을 한곳에 모은다. 지금은 한 파일이고,
매장이 늘면 매장별로 자른다.

## 이 문서를 쓰는 법

- **매장마다 같은 틀을 쓴다.** 나중에 `## 매장:` 아래 한 덩어리를 그대로 잘라
  `docs/store-<코드>.md` 로 옮기면 매장별 원장이 된다. 틀을 매장마다 바꾸지 않는다.
- **모르는 값은 지우지 말고 `미정` 으로 둔다.** 빈칸은 "없음"인지 "아직 안 정함"인지
  구분되지 않는다.
- **비밀값은 적지 않는다.** 비밀번호, Agent 토큰, `PC_SETUP_TOKEN`, Home Assistant 토큰,
  Supabase 키, AnyDesk 무인접속 비밀번호. 여기에는 **어디에 있는지**만 적는다.
- 값이 바뀌면 해당 줄을 고치고 매장 섹션 끝 `이력` 에 한 줄 남긴다.

## 값이 실제로 사는 곳

| 항목 | 진짜 저장 위치 | 이 문서의 역할 |
| --- | --- | --- |
| 매장·타석 | Supabase `stores`, `bays` | 사람이 읽는 사본 |
| 타석 PC·AnyDesk ID | Supabase `bay_pc_registry` (`/admin/remote-access`) | 현장 대조용 |
| 요금표 | Supabase `store_settings.duration_options` (`/admin/pricing`) | 합의된 값 기록 |
| 장비 제어 매핑 | Home Assistant `scripts.yaml` | 어떤 장비가 있는지 |
| 비밀값 | `.env.local`, Vercel 환경변수, HA `secrets.yaml`, DPAPI | **적지 않음** |

### 선행 개발 과제

송도 타석을 관리자 화면에서 켜고 끄려면 코드 수정이 먼저 필요하다. 지금 무인제어는
두 겹으로 시흥점에 묶여 있다.

| 막는 것 | 위치 | 내용 |
| --- | --- | --- |
| 매장 고정 | `src/app/api/admin/automation/route.ts:18` | 시흥 UUID 하드코딩 |
| 매장 고정 | `src/app/admin/dashboard/page.tsx:9` | 타석 상태 화면 |
| 매장 고정 | `src/app/api/store-controller/commands/route.ts:8` | 매장 제어기 |
| 장비 매핑 고정 | `src/lib/automation/device-map.ts` | `bay_01~03` 3타석 고정, `script.bay1_on` 등 시흥 HA 스크립트명 |

요금설정(`api/admin/store-policy`)·미수금(`admin/unpaid`)·예약 준비
(`api/automation/reservation-prepare`)도 같은 하드코딩이지만 **아파트에는 쓰지 않으므로
건드리지 않는다.**

장비 매핑은 `docs/devices-siheung.md` 의 "Next Improvement" 대로 DB(`automation_scenes`,
`automation_devices`)로 옮기는 것이 옳다. 매장이 셋째부터는 소스에 박는 비용이 더 크다.
다만 송도 오픈 일정이 급하면 1단계로 매장 코드 키잉 구조만 만들고 DB 이관은 뒤로 미룬다.
